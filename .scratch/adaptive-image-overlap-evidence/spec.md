# Image-driven adaptive source regularization and Overlap evidence

**Status:** ready-for-agent
**State:** open

## Problem Statement

A lens modeler wants the regions of weak source regularization to follow the arcs when a mass proposal moves their source-plane locations. The current dense and operator image probability models take a fixed source-plane template. Its brightness pattern stays at the original grid nodes as the mass changes, even when the image suggests that the source should move on that grid.

Operator fits also use curvature blocks from their preconditioner to approximate the evidence. The Euclid mock prototype found that overlapping principal windows improved relative scores in several configurations. The prototype uses an older library baseline, an image-wide dense PSF and design matrix for Overlap, and a separate mock workflow for the complete dynamic adaptation sequence. Modelers need the new source prior and scoring method in the maintained library, with bounded GPU work, usable mass gradients, and reliable stage recovery.

## Solution

Use a fixed native image-plane reference arc to generate the adaptive source template at each mass proposal on a fixed source grid. Both ordinary pixelized image probability models accept `adapt_image` in place of `fixed_reg_template`. The source interpolation setting selects the projection weights. Bilinear uses its geometric interpolation weights. Cubic Hermite uses squared weights for adaptation and its signed weights for image prediction and data curvature.

Make Overlap the default operator evidence method and retain explicit Block scoring for controlled comparisons and compatible historical configurations. Deliver the maintained Euclid M1 through M3 sequence, migrate maintained users of the removed interface, and qualify the full Overlap score for bounded, multi-start L-BFGS-B mass optimization in the Euclid mock. Verify the maintained sequence on real VIS data and measure operator resource use on matched GPU configurations.

## Implementation Decisions

1. **Public inputs and fixed grid.** The dense and operator pixelized image probability models accept a concrete, finite `adapt_image` with the same native two-dimensional shape and coordinates as `image_data`. Adaptive evaluations require this image and a validated square `fixed_source_bbox`. The reference is the previous fit's PSF-convolved source arc. Both constructors remove `fixed_reg_template`, and the previously removed `fixed_reg_scale` remains an invalid keyword. Uniform fits can use their existing fixed or inferred grid.
2. **Strengths and activation.** `PixelizedSourceModel` owns `adaptive_reg_rho` and `log_lambda_reg`. Preserve Caskade scalar and dynamic parameter handling and the nonnegative rho constraint. A disabled fixed rho uses the uniform fast path under the existing near-zero convention. A positive fixed rho or a dynamic or unresolved rho requires adaptive inputs even when its initial value is zero. A traced zero yields unit scale. Fit and apply \(\lambda\) separately from the shape of the source precision.
3. **Fixed brightness normalization.** At preparation, clip negative reference intensities to zero. Compute their 99.5th percentile over active native image pixels, use a positive denominator floor of \(10^{-10}\), and clip the normalized reference \(a\) to \([0,1]\). Share this image-plane operation across interpolation modes and backends. Use the fit's selected numerical precision. This reference stays fixed for the lifetime of the prepared model.
4. **Proposal projection.** Share the actual ray indices and interpolation stencil with the forward geometry before native-pixel aggregation. Let \(w_{rj}\) be the interpolation weight for active subpixel ray \(r\) and source node \(j\). Use \(v_{rj}=w_{rj}\) in bilinear mode and \(v_{rj}=w_{rj}^{2}\) in cubic Hermite mode. With \(n_{\rm sub}\) subpixels per native pixel side, define

   \[
   c_j=\frac{1}{n_{\rm sub}^2}\sum_r v_{rj},\qquad
   q_j=\frac{1}{n_{\rm sub}^2}\sum_r v_{rj}a_r ,
   \]

   where \(a_r\) is the fixed normalized brightness of the ray's native parent pixel. Bilinear uses \(u_j=q_j/c_j\) when \(c_j>10^{-8}\) and zero otherwise, as in the prototype. The threshold is internal. Hermite uses \(u_j=q_j/(c_j+\varepsilon)\), with the squared weights computed for each ray before accumulation. Start Hermite qualification at \(\varepsilon=10^{-4}\). The passing value is an internal setting recorded in provenance. The projection is geometric and uses the reference with its original PSF convolution. The imaging and data-curvature paths use the physical interpolation weights.
5. **Source precision and preparation.** Form the node scale \(\exp[\rho(1-u_j)]\) and apply the existing zero-, first-, or second-order finite-difference precision, including its global edge and boundary terms. Prepare the image and grid before tracing. Reuse invariant mapping and projected brightness when mass and geometry are fixed. Cache weighted prior quantities only when their projection and rho dependencies are invariant, including Caskade registered pointer dependencies. A fixed reference and a fixed rho still yield a proposal-dependent precision when mass moves the rays. The dense joint data cache additionally depends on the unit-amplitude lens-light bases. Apply dynamic strengths outside invariant caches and keep evaluation free of Python-side cache writes.
6. **Evidence interface.** The operator model accepts `evidence_logdet` with `overlap` as the default and `block` as the explicit preconditioner-based evidence calculation. Use the prototype tile width of 10 as the Overlap baseline. `evidence_block_size` controls those tiles independently of the solver `block_size`. The dense model uses complete determinants. Use the existing solver objectives, position penalty, noise normalization, and unconstrained-curvature determinant convention when applying a nonnegative solver.
7. **Overlap windows.** For whitened design \(F\), prior precision \(H\), and posterior curvature \(P=F^\mathsf{T}F+H\), evaluate the source determinant ratio as signed sums of exact principal-window log determinant differences. Tile the source grid, include the contiguous two-by-two tile windows, subtract horizontal and vertical strip intersections, and add back their common interior tile intersections. Use the corresponding full-grid window when one window spans the source. Include partial edge tiles. Form each data Gram from the physical source stencil, mask, subpixel integration, PSF and noise. Restrict the global prior to the window with cross-window diagonal contributions intact.
8. **Joint semi-linear inversion.** Use the validated unit-amplitude lens-light bases and positive `lens_light_regularization` in both backends. The operator MAP solve and explicit Block evidence use the established Block–Schur preconditioner with spectral damping as needed. For Overlap, use the source block \(A\) in the window sums, the physical source–lens-light cross curvature \(B\), and the full lens-light curvature block \(D\). Solve \(AX=B\) with the complete source curvature and compute the small Schur log determinant through the prototype's augmented-residual QR. Add \(\log\det(D-B^\mathsf{T}X)-\log\det H_{\rm lens}\) once. The lens-light prior enters the score with its existing physical precision.
9. **Bounded operator work.** Assemble windows with bounded source columns and the existing masked PSF action. Keep both scoring and reverse-mode work free of image-wide dense PSF, full image-by-source design, and global source curvature allocations. Select a conservative automatic Overlap chunk width through qualification and honor explicit `vectorized_chunk_size`, preserving the sampler's batch input and output. Prepare or cache invariant window data only within the bounded resource contract.
10. **Reconstruction and failure reporting.** `evaluate` and `evaluate_with_diagnostics` use one primary observation-data solve and the same proposal state for residuals, precision, score and reconstruction. Pass the actual used scale to host diagnostics. Keep `forward_model` on the reconstruction-only path, skipping score-only determinants and auxiliary Schur solves. Retain the public compiled result structure and existing primary-solve failure conventions. For an auxiliary evidence failure, apply the existing finite score penalty for sampling and the invalid-gradient convention for optimization. Report the score failure separately and keep any valid primary reconstruction available.
11. **Reference product.** Export the PSF-convolved native source component from the valid M1 inversion through the existing component diagnostics. Save it as `adapt_image` alongside the source pixels and fitted grid. `source_image` continues to represent the source-plane raster. Store the parent model point and the observation, mask, PSF, sampling, interpolation and boundary provenance needed to align and reproduce the reference.
12. **Maintained Euclid stages.** Use the current maintained stage definitions. M1 exports the reference and source grid. M2 fixes the M1 mass and calibrates \((\lambda,\rho)\) under the new adaptive objective. M3 fixes the chosen M2 strengths, reuses the M1 reference and grid, and changes the projection with the mass. Keep the selected score and preparation settings available to fitting, plotting, and artifact recovery.
13. **Recovery and compatibility.** Record the actual evidence method at every operator-scored stage, including uniform stages, along with the applicable tile and solver settings. Fingerprint the reference image, observation and grid identity, interpolation and boundary, adaptation recipe and coverage settings, and upstream stage identity. Record fixed strengths where they affect a downstream fit. Resume a saved objective only when its relevant settings match. A legacy M1 with verifiable source pixels, mass, grid, interpolation, mask and PSF can serve as an upstream reference through the existing component renderer. Rebuild the producer when this information is missing. Recalibrate M2 and rerun M3 for the new adaptive objective. Explicit Block supports historical comparisons with matching prior and scoring configurations.
14. **Caller migration and J0946.** Migrate maintained callers of the removed constructor input as part of the same deliverable, including cases whose reference comes from M0. Include the minimal migration of the two documented J0946 macro producers. A fresh handoff freezes the actual adaptive scale from the selected M3 draw and records the scoring method and provenance from the same evaluation. Downstream fixed-scale potential correction consumes that product through its existing `source_scale` contract. Require matching adaptation and evidence provenance for paired M4/M5 comparisons, and use archived handoffs with their recorded scale and objective.
15. **Delivery order.** Establish the shared projector, prior and diagnostics. Implement and verify both evidence choices, then migrate the maintained stages and callers and remove the old constructor keyword. Complete numerical, optimization, workflow and resource qualification before finalizing the internal Hermite coverage value and publishing the updated guide. Keep the public migration in one usable deliverable.

## Testing Decisions

1. **Confirmed seams.** Exercise both probability models through `evaluate`, `evaluate_with_diagnostics` and `forward_model`. Use the public array-returning model and Caskade parameter order for automatic differentiation, and `make_likelihood` for scalar and batched sampling checks. Test reference export, compatibility and recovery through the maintained stage interfaces and `reconstruct_component_images` for archived reconstructions. Prefer assertions about images, scales, scores, gradients, validity and serialized results over private cache layouts.
2. **Independent projection checks.** On a small fixed grid, assemble a reference from explicit masked subpixel rays and their native brightness. Check both interpolations, the square-before-aggregation rule, finite input validation, zero and weak coverage, out-of-grid support and static and dynamic rho including zero. Verify dense/operator agreement of the applied scale and reconstruction under matched solves. Exercise fixed and changing masses, registered pointer dependencies, and repeated or batched proposals to catch stale prepared state. Existing fixed-grid, interpolation and adaptive-precision regressions are prior art.
3. **Score and solver checks.** Use a complete small-matrix calculation for the single-window determinant and an independent combination of exact principal windows for multi-window scores. Exercise partial tiles, the smallest supported grids, all three finite-difference orders, asymmetric PSF, mask, subpixel integration and both interpolations. Compare source-only and joint scores on the same linear solution. Exercise PCG and PNPG, verify explicit Block on a matched baseline, check joint Schur normalization and separate auxiliary failure from primary convergence. Existing one-solve diagnostics and dense/operator curvature comparisons supply the patterns.
4. **Gradient checks.** Compare Float64 automatic derivatives of the reconstruction and full evidence with independent numerical derivatives in valid fixed-grid cases with moving mass and dynamic regularization. Include a controlled Hermite ray crossing and test the conditional source prior separately from the full evidence. Exercise joint evidence and the existing locally stable PNPG active-set regime. Control or record the position-penalty regime when comparing derivatives. Use the existing fixed-bbox Hermite autodiff regressions as the starting seam.
5. **Original mock and multi-start optimizer.** Reuse the archived no-noise Euclid mock with its RMS weighting, 80×80 grid, mask, PSF, subpixel integration and recorded reference producer. Recalibrate M2 and rerun M3 with the new prior. Compare Block, Overlap and a complete determinant reference at matched proposals, with a shared primary solve for scoring comparisons. Report absolute score offsets, centered errors and ranking separately. Check the slope scan and gradient first, then maximize the model's full Overlap score in Float64 with L-BFGS-B over all free M3 mass parameters and their existing physical bounds. Use the score with its configured position penalty and adaptive source prior. Predeclare multiple reproducible starts, solver settings and projected-gradient qualification criteria. Record native line-search status, valid finite endpoint scores and gradients, projected gradients and endpoint basins for every start. Use these complete-score checks to qualify the Hermite coverage setting.
6. **Stages and real VIS.** Extend the small maintained Euclid regression to exercise M1 export, M2 calibration assembly and M3 consumption, plus matched resume, changed provenance, compatible legacy inputs and missing reference data. Check the J0946 handoff and paired-score compatibility on focused in-scope regressions. Run the maintained Euclid sequence through M1, M2 and M3 on real VIS data on the available host, using verified upstream inputs and fresh artifacts where required. Record its settings and outcomes separately from the original mock.
7. **Same-host GPU measurements.** Run the 80×80 source-only mock and a representative joint semi-linear inversion on the same device. Record preparation, first compilation, warmed score and gradient timings, peak device memory, and the effect of inner chunk width at matched sampler batches. Check bounded allocation in forward and reverse scoring. Record the comparison with Block at the same physical configuration. Use the repository's existing bounded operator benchmark and resource reports as prior art.
8. **Verification placement.** Keep core numerical behavior in library tests, stage and artifact behavior in example tests, and timing and memory measurements in benchmarks. Run these suites in separate processes in the `tinylens_gpu` environment. Use regenerable small fixtures for routine collection and explicit data inputs for the full mock and VIS qualifications. Retain the runner, configurations and small result summaries needed to interpret the runs. Follow the repository scope rule when selecting shared test node IDs.

## Out of Scope

- B1938+666, including its dedicated workflows, modeling, replays and tests.
- Changes to the fixed-strength source–potential correction objectives, gradient policies, or local Gauss–Newton evidence.
- A general public mass optimizer, a nonlinear mass-prior MAP objective, or a public coverage-offset control.
- New source interpolation modes, solver families, or lens-light model changes. The prototype's alternative MGE foreground subtraction and removal of Stage L are separate modeling choices.
- Rewriting archived posteriors or handoffs to assign them the new objective, and general scientific claims beyond the documented qualification configurations.

## Further Notes

- The agreed implementation baseline is `codex/lbfgs-potential-correction@17abd1b`. The prototype `5d9fa5d` supplies the bilinear projection, Overlap window algebra and joint QR experiments. Its handoff and archived results describe their original configurations. The first release qualifies the code and model specified here.
- This spec supersedes the [fixed-source-template adaptive specification](../adaptive-regularization/spec.md) for the integration. The [dense fixed-grid cache record](../dense-pixelized-fixed-grid-cache/spec.md) and [source interpolation specification](../pixelized-source-interpolation/spec.md) explain the existing interfaces that it builds on. The [Block–Schur ADR](../../docs/adr/0001-use-block-schur-for-joint-operator-inversion.md) and [unit-amplitude basis ADR](../../docs/adr/0002-require-unit-amplitude-lens-light-bases.md) govern joint semi-linear inversion.
- The archived mock uses an 80×80 grid and its SIE M1 reference. The maintained VIS workflow has a distinct grid and EPL M1. Attribute numerical comparisons to the workflow that produced them. The available legacy VIS M1 cache lacks the required source package, so the real-data qualification needs a valid M1 producer.
- The earlier fixed-mass template comparison and conditional-prior slope scan motivate the squared Hermite projection and the initial coverage offset. The complete Overlap and multi-start runs qualify their use in optimization. The separate [L-BFGS-B potential-correction specification](../lbfgs-potential-correction/spec.md) governs optimization over source and potential fields using a fixed scale.
