> Historical experiment. FISTA was removed on 2026-10-24 after migrating its

## Question and scope

Can the current PNPG example at
`examples/pix_src_demo_operator/simple/pix_src_lens_light_mge/fit_joint.py`
use the existing FISTA solver without changing the physical model?

The direct replacement fails at FISTA's default 1000 iterations and
`rtol=1e-5` at all three tested regularization settings. Increasing to 5000
iterations does not fix those failures. A 50000-iteration FISTA solve passes
the forward convergence gate at the true nonlinear parameters with
`log_lambda_reg=-8`, with evidence close to a high-iteration PNPG solve,
but costs approximately 3.8 seconds per scalar evaluation instead of 0.15
seconds for the example's 1000-iteration PNPG configuration.

These are conditional inversion checks, not a completed nested-sampling
run. The example and both solver implementations were left unchanged.

## Configuration

- NVIDIA GeForce RTX 5080; JAX 0.7.1; CUDA device; x64 disabled.
- Data generated by the unchanged `sim_data.py`, seed 42, simulation
  `nsub=16`; image shape 100 x 100 with 5024 fitted pixels.
- Twenty Gaussian lens-light bases, with the original widths and weak
  amplitude regularization `1e-6`. Their four shared geometry parameters
  remain dynamic, as in the example.
- Source grid 80 x 80, first-order regularization, inversion `nsub=4`,
  dynamic source bbox with padding 0.2, default source block size 10.
- Original mass/light initial values, equal to their true nonlinear values;
  only `log_lambda_reg` is scanned over 0, -8, and -6.
- Original position penalty, data mask, source seed mask, float precision,
  PCG warm start, and physical curvature operator are retained.
- Scalar `jax.jit(model.evaluate)` measurements, with device synchronization.
  Times below are medians of three warmed evaluations, excluding compilation
  and setup. They are not vectorized sampler timings.

Data image SHA-256:
`16408b1f4c2212a8fba9fd033cd27fe18e293dcee9ce7ffbd12bf8d2adfde00d`.

## Results at log_lambda_reg = -8

| Solver | Iterations | rtol | Forward gate passes | log evidence | Warm seconds |
|---|---:|---:|---|---:|---:|
| PNPG | 1000 | 0.02 | yes | 2685.861572 | 0.145 |
| PNPG | 5000 | 0.02 | yes | 2686.236572 | 0.596 |
| PNPG | 20000 | 0.02 | yes | 2686.166260 | 2.284 |
| FISTA | 1000 | 1e-5 | no | -1e10 penalty | 0.115 |
| FISTA | 5000 | 1e-5 | no | -1e10 penalty | 0.417 |
| FISTA | 20000 | 1e-5 | no | -1e10 penalty | 1.549 |
| FISTA | 5000 | 1e-3 | yes | 2683.482666 | 0.415 |
| FISTA | 50000 | 1e-5 | yes | 2686.150635 | 3.817 |

All successful reconstructions have non-negative source and lens-light
amplitudes. The 50000-iteration FISTA result has chi-square per fitted datum
0.927775, compared with 0.927796 for 20000-iteration PNPG. Their log evidence
differs by 0.015625, whereas the loose-tolerance 5000-iteration FISTA result
differs from that PNPG result by -2.683594. The close residual statistic alone
therefore does not establish adequate accuracy of the regularized objective.

At `log_lambda_reg=-6`, 1000- and 5000-iteration default-tolerance FISTA
also fail. FISTA at 20000 iterations passes, giving log evidence 1997.525513
and 1.542 seconds per evaluation. PNPG at 20000 iterations gives 1997.607544.
Loose-tolerance FISTA at 5000 iterations gives only 1994.158325.

At `log_lambda_reg=0`, default-tolerance FISTA at 1000 and 5000 iterations
fails; 5000 iterations with `rtol=1e-3` passes, with log evidence -83559.992188
versus -83559.914062 for PNPG at 1000 iterations. That strongly regularized
point has a poor fit, with chi-square per fitted datum approximately 27.35.

## Interpretation and limits

### Nearby parameter checks

An additional run compares FISTA at 50000 iterations against PNPG at 20000
iterations at the same five parameter vectors. Four vectors perturb the
true nonlinear values and `log_lambda_reg=-8`, using NumPy seed 24, Gaussian
standard deviations 0.003 for Einstein radius/ellipticities, 0.001 arcsec
for centers, and 0.1 for log regularization. Both solvers pass their forward
gate at all five points, and all source/lens amplitudes are non-negative.
Nearby-run times use one warmed repeat per point rather than three.

| Point | FISTA log evidence | PNPG log evidence | FISTA minus PNPG |
|---|---:|---:|---:|
| Initial -8 | 2686.025635 | 2686.252197 | -0.226562 |
| Nearby 1 | 2590.226807 | 2590.422119 | -0.195312 |
| Nearby 2 | 2672.437744 | 2672.468994 | -0.031250 |
| Nearby 3 | 2637.021729 | 2637.076416 | -0.054688 |
| Nearby 4 | 2571.584229 | 2571.724854 | -0.140625 |

The repeated initial point also shows cross-run numerical variation: for
FISTA, 2686.150635 in the first run versus 2686.025635 here; for PNPG at
20000 iterations, 2686.166260 versus 2686.252197. Thus the first 0.015625
agreement should not be interpreted as reproducible accuracy at that level.
The experiment did not isolate the cause of this float32 variation.
These local checks do not cover the full prior or establish reliable
nested-sampling behavior.

### Conclusions

- FISTA and PNPG use different convergence metrics. Their `rtol` values
  cannot be compared directly or copied between solvers.
- PNPG at 1000 iterations is a baseline, not an exact reference: raising its
  budget changes evidence by approximately 0.3 at -8 and 1.1 at -6. Even its
  higher-iteration evidence is not perfectly monotonic in float32. These
  runs establish numerical comparison points, not an exact NNLS solution.
- At the same nonlinear parameters, the curvature/determinant approximation
  and position penalty are common to both solvers. Evidence differences
  assess differences in their regularized reconstruction energies, subject
  to floating-point error.
- FISTA's forward convergence flag does not establish validity of its
  implicit derivative. For example, the 50000-iteration -8 run reports a
  componentwise `kkt_violation` of approximately 0.00228, above the implicit
  wrapper's default relative KKT threshold of 1e-4. No gradient validation
  was performed; the example also uses a dynamic bbox.
- No MGE basis reduction, stronger physical prior, preconditioning change,
  or solver algorithm modification was used to make FISTA pass.
- The evidence remains the operator backend's existing curvature
  approximation. This experiment does not validate the exact normalization
  of a constrained posterior.

Retain PNPG for this example for now. The existing FISTA can produce a locally
similar non-negative reconstruction with a very large iteration budget, but
it has not demonstrated an efficient replacement. Removing PNPG first would
leave the current 20-MGE example without its validated routine solver path.

## Reproduction and artifacts

The harness reuses the example's setup and explicitly stops before sampling:
`.scratch/fista-mge-validation/compare_solvers.py`. JSON diagnostics and
compressed reconstruction arrays are saved under its ignored `output/`
directory. Source and model arrays from failed solves are deliberately zero,
following the production model's failure contract.

From the repository root:

```bash
source ~/anaconda3/bin/activate
conda activate tinylens_gpu
MPLBACKEND=Agg XLA_PYTHON_CLIENT_PREALLOCATE=false python examples/pix_src_demo_operator/simple/pix_src_lens_light_mge/sim_data.py
python .scratch/fista-mge-validation/compare_solvers.py --solver pnpg --iterations 1000
python .scratch/fista-mge-validation/compare_solvers.py --solver pnpg --iterations 5000 --log-lambda -8 -6
python .scratch/fista-mge-validation/compare_solvers.py --solver pnpg --iterations 20000 --log-lambda -8 -6
python .scratch/fista-mge-validation/compare_solvers.py --solver fista --iterations 1000
python .scratch/fista-mge-validation/compare_solvers.py --solver fista --iterations 5000
python .scratch/fista-mge-validation/compare_solvers.py --solver fista --iterations 5000 --rtol 1e-3
python .scratch/fista-mge-validation/compare_solvers.py --solver fista --iterations 20000 --log-lambda -8 -6
python .scratch/fista-mge-validation/compare_solvers.py --solver fista --iterations 50000 --log-lambda -8
python .scratch/fista-mge-validation/compare_solvers.py --solver fista --iterations 50000 --log-lambda -8 --nearby-points 4 --timing-repeats 1
python .scratch/fista-mge-validation/compare_solvers.py --solver pnpg --iterations 20000 --log-lambda -8 --nearby-points 4 --timing-repeats 1
```
