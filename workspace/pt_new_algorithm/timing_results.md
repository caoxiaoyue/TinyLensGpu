# 完整 Mock 速度补测：AD + L-BFGS 与原 dense LM

2026-11-03。**成功通过原收敛门限时，新方法在这套 Mock 上明显更快。** 编译后的有效样本中，有扰动约 1.1 秒，对照的 dense LM 约 33.8 秒；无扰动约 0.70 秒，对照约 13.9 秒。

**但不能把这些数字表述为稳定保证的 20–30 倍加速。** 有扰动的新方法 3 次 warm 重复中只有 2 次通过梯度门限；一次失败已保留，并没有混入成功耗时。进一步收紧内部 ftol 后，仍出现未过门限的重复运行。

## 实际测量结果

同一 RTX 5080、float64、原始 200×200 Mock、同一原真值节点源初值、相同物理先验和原梯度验收。以下是已编译程序的重复执行，**每次重新计算白化矩阵及其分解，不复用已算好的矩阵或磁盘缓存**。

| 案例 / 方法 | 通过 / warm 尝试 | 通过样本的耗时范围 / 秒 | 通过样本中位数 / 秒 |
| --- | ---: | ---: | ---: |
| 有扰动：原 dense LM | 3 / 3 | 33.7906–33.8274 | 33.8023 |
| 有扰动：AD + L-BFGS | 2 / 3 | 1.0723–1.1211 | 1.0967 |
| 无扰动：原 dense LM | 3 / 3 | 13.9076–13.9365 | 13.9170 |
| 无扰动：AD + L-BFGS | 3 / 3 | 0.7012–0.7177 | 0.7043 |

成功样本中位数的条件比值分别为 **30.82× / 19.76×**。这些不是包含失败后重试成本的可靠吞吐率；没有测量自动重试策略，也没有删除失败记录来计算一组“全部成功”的加速比。

各 worker 首次调用（含求解器 JIT，几何/数据已准备）也单独记录：

| 案例 | LM 的共同恢复口径 / 秒 | LM 完整公共 fit / 秒 | 新方法 / 秒 |
| --- | ---: | ---: | ---: |
| 有扰动 | 38.2489 | 38.4932 | 5.1288 |
| 无扰动 | 18.4365 | 18.6889 | 4.6948 |

首次调用都通过原物理梯度门。这里没有把 Python 启动、CUDA context、Mock 生成和几何构建算进去；也没有对两者共同预热相同的小矩阵 Cholesky。LM 扣除的先验 logdet 可能提前初始化线性代数运行时，因此首次调用表保留原始时间，不作为严格冷启动加速比，主结论采用 warm 数据。

## 时间包括与不包括什么

共同口径从已准备的 problem 开始，到完成收敛验收并生成原始图像、源和势场产品：

- 新方法：初始 AD GN 矩阵、白化 Cholesky、全部目标/梯度与 CPU/GPU 传输、L-BFGS 和 line search、终点当前 GN 对角及梯度证书、非线性重渲染和物理场。
- 原 LM：先验矩阵构建、每一步完整当前 Jacobian/GN 曲率、全部增量分解、接受/拒绝和阻尼控制、终点当前曲率与梯度检查、相同的图像和场产品。
- 排除双方绘图、文件写入、checkpoint、恢复误差统计和历史结果比较。计时前后显式同步 GPU 输出。
- 原 LM 公共 fit 额外计算 prior normalization、posterior logdet/evidence。实验保留这些真实计算和 SPD 检查，只量出对应区间并从共同恢复时间扣除，没有用假 logdet 跳过任何原算法步骤。完整公共 fit 时间另列。

Warm 计时保持编译函数的身份与参数形状；新方法的当前点和 Cholesky 作为动态参数传入。原脚本每次创建新 JIT 闭包的方式不能直接称为 warm，因此计时脚本整理了可复用函数；数学上的目标、初始白化和优化算法保持一致。没有使用上一轮保存的白化矩阵。

因此，这些是计时整理版本的耗时，不是把原研究脚本的旧 solve_seconds 与 LM 全时间直接相除。每个 method/case 用独立进程，按先首次、再 3 次 warm 串行测量；JAX persistent compilation cache 为 None。

## 为什么单步便宜很多

当前 dense LM 每次迭代都构造完整当前 Jacobian 和大曲率矩阵，并求解增量。AD + L-BFGS 只在起点构造一次白化矩阵，后续迭代主要做正向图像和自动微分梯度。

有扰动时，LM 仍为 46 个接受步；新方法成功 warm 样本是 157 / 193 步。新方法步数更多，但每步明显便宜。因此这项优势来自这里的求解策略及实现，不等于自动微分本身总比解析求导快。**原 LM 也在使用 JAX 和 GPU。**

一组成功的 warm 有扰动新方法，完整 1.0723 秒分解为：

| 组件 | 秒 |
| --- | ---: |
| 重新构造初始 AD 矩阵 | 0.4604 |
| Cholesky 与检查 | 0.0394 |
| 梯度准备 / 初始检查 | 0.0087 |
| 全部 L-BFGS 优化 | 0.4050 |
| 终点当前梯度证书 | 0.1494 |
| 图像与场产品 | 0.0094 |

这也说明不能只把 0.405 秒当作新方法完整时间。

## 新发现的停止稳定性问题

默认 ftol=1e-15 时，有扰动第 3 次 warm 运行在 0.9923 秒结束，但：

- SciPy 返回 success，原因是目标相对变化小。
- 当前物理尺度梯度为 **7.1479e-4**，高于约 **5.0098e-4** 门限。
- 独立解析梯度给出相同结果；在相同 GN 尺度下两者差约 5.6e-14，排除了证书本身错误。
- 这行不是有效恢复速度样本，完整保留在原始记录和汇总的 failed_rows 中。它恰是最快的一次，不能将它当作更好的性能。

单独只将 ftol 收紧到 0，目标、初值、预条件、原物理门限均不变，得到：

| ftol=0 探针 | 耗时 / 秒 | 梯度 | 门限 | 结果 |
| --- | ---: | ---: | ---: | --- |
| 首次 | 5.1623 | 3.3641e-4 | 5.0098e-4 | 通过 |
| 第 1 次 warm | 1.1028 | 7.7226e-4 | 5.0098e-4 | 未通过 |

这说明简单收紧 ftol 尚未解决停止问题。当前记录支持“目标变化停止不能替代外部梯度验收”，还没有定位其具体数值机制；不能仅凭这些标量就断言终点位于某个插值折点。

此前完整恢复实验的四个终点确实都通过；本次重复计时没有推翻其记录，但补充揭示了重复计算中的失败，不能用四个成功端点推导普遍稳定性。正式整合前需要单独验证外部验收和必要的继续求解/重启政策，不能放宽物理梯度门限来让计时通过。
